# DeviceServiceImpl — 设备服务实现

设备管理的核心业务逻辑层，包含设备 CRUD、状态更新、心跳检测触发等。

## 核心方法

### updateDeviceStatus(Long deviceId, String status)

设备状态更新入口，**唯一写 `iot_device.status` 字段的方法**。由以下两个来源触发：

1. **`DeviceHeartbeatTask.heartbeatCheck()`** — Quartz 定时任务（每分钟），ping 设备 IP 后调用
2. **`AlertWebhookController`** — AlertManager 告警 Webhook 回调

#### 副作用链

状态变更时（`oldStatus ≠ newStatus`），自动触发以下操作：

```
updateDeviceStatus()
  ├── 写入 DeviceStatusLog（状态变更日志表）
  ├── 状态为 OFFLINE → createRepairOrder() 自动创建维修工单
  │   └── 发送 "device_offline_alert" 短信（含维修口令 token）
  └── 状态为 ONLINE → 发送 "device_online_notify" 短信
```

#### 幂等性

- 若 `newStatus == oldStatus`，直接返回 0，不写入日志、不发送短信
- `@Transactional` 保证日志写入 + 状态更新原子性

#### 短信发送条件

仅当设备配置了 `responsiblePhone` 且状态在 ONLINE↔OFFLINE 之间切换时才发送。UNKNOWN→ONLINE/OFFLINE 的过渡不触发短信。

## 依赖

- `DeviceMapper` — 设备表读写
- `DeviceStatusLogMapper` — 状态变更日志写入
- `DeviceRepairServiceImpl` — 离线自动创建维修工单
- `SmsUtil` — 短信通知（device_offline_alert / device_online_notify）
