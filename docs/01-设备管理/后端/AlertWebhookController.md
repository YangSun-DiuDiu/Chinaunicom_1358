# AlertWebhookController — AlertManager 告警回调接口

接收 AlertManager 推送的设备告警，解析后更新设备在线状态。**无需登录**（`SecurityConfig` 中 `permitAll()`）。

## 接口列表

| 方法 | HTTP | 路径 | 权限 | 说明 |
|------|------|------|------|------|
| `webhook` | POST | `/device/alert/webhook` | 无（匿名） | 接收 AlertManager 告警推送 |

## AlertManager 推送 Payload 格式

```json
{
  "receiver": "ruoyi-webhook",
  "status": "firing",
  "alerts": [
    {
      "status": "firing",
      "labels": {
        "alertname": "DeviceDown",
        "device_name": "核心交换机-01",
        "device_type": "switch",
        "instance": "115.159.194.149:9116",
        "job": "snmp-huawei-switch",
        "severity": "critical",
        "site": "总部园区",
        "snmp_ip": "116.148.212.150",
        "target": "116.148.212.150"
      },
      "annotations": {
        "summary": "设备 核心交换机-01 离线",
        "description": "核心交换机-01(116.148.212.150) 在 总部园区 离线，类型: switch"
      },
      "startsAt": "2026-08-09T09:06:00.000Z",
      "endsAt": "0001-01-01T00:00:00Z",
      "fingerprint": "abc123def456"
    }
  ],
  "groupLabels": {},
  "commonLabels": {},
  "commonAnnotations": {},
  "externalURL": "http://115.159.194.149:9093",
  "version": "4",
  "groupKey": "{}:{}"
}
```

## 核心逻辑

1. **接收 payload** — Spring `@RequestBody Map<String, Object>` 接收 JSON
2. **遍历 `alerts[]`** — 提取每条告警的 `status`、`labels.target`（设备 IP）
3. **IP 解析** — 若 `target` 含端口（`ip:port`），截取 IP 部分
4. **状态映射** — `firing` → OFFLINE，`resolved` → ONLINE，其他值跳过（防误报）
5. **设备匹配** — 按 IP 查询 `iot_device` 表，**精确全等过滤**（XML 使用 LIKE 模糊查询需二次过滤，避免 `192.168.1.5` 误命中 `192.168.1.50`）
6. **调用 `deviceService.updateDeviceStatus(deviceId, targetStatus)`** — 触发状态更新 + 日志 + SMS 副作用链

## 安全设计

- 标注 `@Anonymous` 或在 `SecurityConfig` 中 `permitAll()`，AlertManager 无登录态
- 仅处理合法状态（firing/resolved），未知 `status` 跳过不更新，避免误报触发短信
- NPE 防护：`payload` null、`alerts` null、`labels` null、`target` null 逐层防御

## 依赖

- `IAlertWebhookService` / `AlertWebhookServiceImpl` — 告警 payload 解析 + 设备匹配
- `IDeviceService` / `DeviceServiceImpl` — 设备状态更新
