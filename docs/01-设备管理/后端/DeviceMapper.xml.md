## 核心 SQL

### selectDeviceList — 列表查询（2026-08-10 重构）

```xml
<select id="selectDeviceList" parameterType="Device" resultMap="DeviceResult">
    select d.device_id, d.dept_id, d.device_name, ..., sd.dept_name
    from iot_device d
    left join sys_dept sd on d.dept_id = sd.dept_id
    <where>
        <if test="deptId != null and deptId != 0">
            AND (d.dept_id = #{deptId} OR d.dept_id IN (
                SELECT t.dept_id FROM sys_dept t
                WHERE find_in_set(#{deptId}, ancestors)
            ))
        </if>
        ...
    </where>
</select>
```

采用**内联 SQL** 而非复用 `selectDeviceVo` 片段，因为后者被 `selectDeviceById` 等不需要部门名称的查询共享，加入 LEFT JOIN 会引入不必要的联表开销。

### updateDevice — 部门变更支持（2026-08-10 修复）

```xml
<if test="deptId != null">dept_id = #{deptId},</if>
```

此前 insert 有 `dept_id` 但 update SET 块遗漏，导致修改设备时无法变更归属部门。现已补齐。

### 部门过滤 find_in_set

选中父部门时递归包含所有子部门的设备数据，实现完整的组织架构树筛选。
