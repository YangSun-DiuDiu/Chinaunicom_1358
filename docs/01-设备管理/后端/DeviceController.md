# DeviceController — 设备管理接口

设备管理核心控制器，提供 CRUD、统计、拓扑、报修、部门树等 11 个 REST 接口，统一挂载在 `/device` 路径下。

## 核心逻辑

### 部门树 (deptTree)

```java
@GetMapping("/deptTree")
public AjaxResult deptTree(SysDept dept) {
    return success(deptService.selectDeptTreeList(dept));
}
```

直接委托 `ISysDeptService.selectDeptTreeList()`，返回全量部门树结构（含 `id`、`label`、`children`）。前端同时用于两个场景：

1. **TreePanel 侧边栏**：点击节点触发 `handleDeptNodeClick` → `queryParams.deptId = data.id` → `list()` 带 deptId 过滤
2. **表单 Treeselect**：新增/编辑设备时选择归属部门

### 设备列表 (list) — 部门过滤

```java
@GetMapping("/list")
public TableDataInfo list(Device device) {
    startPage();
    List<Device> list = deviceService.selectDeviceList(device);
    return getDataTable(list);
}
```

Spring MVC 自动将 query string 的 `deptId` 绑定到 `Device.deptId`（继承自 BaseEntity）。Mapper 层通过 `find_in_set(ancestors)` 实现选中父部门时包含所有子部门设备：

```sql
AND (d.dept_id = #{deptId} OR d.dept_id IN (
    SELECT t.dept_id FROM sys_dept t WHERE find_in_set(#{deptId}, ancestors)
))
```

同时 `selectDeviceList` 通过 `LEFT JOIN sys_dept sd ON d.dept_id = sd.dept_id` 获取 `sd.dept_name`，用于前端表格展示部门名称。

### 拓扑树 (topology)

递归构建父子设备层级关系。过滤掉完全孤立的设备（未配置 parent_id 且不被其他设备引用），只展示有拓扑关联的设备节点。每个节点包含 deviceId、deviceName、deviceType、status、ipAddress、model、location、icon、cableType 等字段。

## 依赖

- `IDeviceService` — 设备 CRUD 业务层
- `ISysDeptService` — 部门树数据（若依系统服务）
- `SmsUtil` — 设备报修短信发送

## 注意事项

- **设备状态不由前端提交**：新增/修改时表单中的 `status` 字段被 `delete this.form.status` 移除，设备状态完全由 Prometheus → AlertManager → Webhook 告警链路驱动
- **deptTree 端点与用户管理共用**：`device:list` 权限即可访问，前端不需要 `system:user:list` 权限即可加载组织架构树
- **子部门过滤**：选中父部门时自动包含子部门设备，由 Mapper 层 `find_in_set` 实现
