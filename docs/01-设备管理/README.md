# 设备管理

设备管理模块负责园区所有网络设备（交换机、防火墙、路由器等）及智能化终端（人员通行、车辆通行、视频监控）的统一管理，涵盖设备 CRUD、在线状态监控、故障报修、配件管理、SNMP 配置、拓扑可视化和心跳日志。

### 关键时间参数

| 环节 | 间隔/延迟 | 说明 |
|------|----------|------|
| SNMP Exporter 采集 | 每 60s | Prometheus `scrape_interval` |
| 告警规则评估 | 每 60s | `device_rules.yml` `interval: 60s` |
| 告警持续判定 | `for: 2m` | 连续 2 分钟 `up==0` 才触发，避免误报 |
| AlertManager 分组等待 | `group_wait: 10s` | 收到告警后等待 10s 批量发送 |
| Webhook 处理延迟 | < 1s | 同机房内网通信 |
| **端到端延迟** | **约 3~4 分钟** | 从设备断网到 SMS 通知发出 |

### 双轨监控体系

| 监控对象 | 检测方式 | 状态 |
|---------|---------|------|
| **iot_device（设备管理）** | Prometheus SNMP → AlertManager Webhook | ✅ 生产运行中 |
| **iot_person_access_device（人员通行）** | DeviceHeartbeatTask Java Ping | ✅ 运行中 |
| **iot_vehicle_access_device（车辆通行）** | DeviceHeartbeatTask Java Ping | ✅ 运行中 |
| **iot_video_device（视频监控）** | DeviceHeartbeatTask Java Ping | ✅ 运行中 |

> **历史说明**: iot_device 原由 `DeviceHeartbeatTask.checkIotDevices()` 执行 Java Ping 检测（已注释于 2026-07-12），迁移至 Prometheus/AlertManager 驱动。原因：Java Ping 只能检测网络可达性，无法感知设备 SNMP 服务状态；Prometheus 可获取设备运行时长、端口流量等多维度指标。

## 核心流程

### 1. 设备状态变更流程 (Prometheus 驱动)

设备断网 → SNMP 采集超时 → `up=0` → 2 分钟后 Prometheus 触发 `DeviceDown` 告警 → AlertManager 推送到 Webhook → `updateDeviceStatus(OFFLINE)` → 写入状态日志 → 自动创建维修工单 → 发送短信通知负责人。

设备恢复 → `up=1` → AlertManager 发送 `resolved` → Webhook 收到 → `updateDeviceStatus(ONLINE)` → 写入状态日志 → 发送恢复通知短信。

### 2. 设备 CRUD 流程

标准若依单表 CRUD：Controller 分页查询/新增/修改/删除 → Service 校验 → Mapper XML → iot_device 表。新增/修改时 `status` 字段不由前端提交（表单中 `delete this.form.status`），完全由监控链路驱动。

### 3. 报修流程

设备离线 → 自动创建维修工单（可选手动报修）→ 维修员接单 → 维修完成 → 输入维修口令（token）验证 → 工单关闭。手动报修发送 `device_repair` 短信，自动离线仅发 `device_offline_alert` 短信，**避免短信双发**。
