# 设备列表页

设备管理的列表页面，包含搜索区、统计卡片、设备表格、新增/修改弹窗。

## 设备状态渲染

设备状态**不使用若依字典翻译**，采用硬编码 `v-if` 判断：

| 状态值 | 标签样式 | 显示文本 |
|--------|---------|---------|
| `ONLINE` | `el-tag type="success"` 绿色 | 在线 |
| `OFFLINE` | `el-tag type="danger"` 红色 | 离线 |
| `UNKNOWN` | 默认灰色 | 未知 |

```html
<el-tag v-if="scope.row.status === 'ONLINE'" type="success">在线</el-tag>
<el-tag v-else-if="scope.row.status === 'OFFLINE'" type="danger">离线</el-tag>
```

## 关键功能

- **统计卡片**：页面顶部展示在线/离线/未知设备数量，通过 3 个独立 API 调用统计（`pageSize: 1` 仅取 total）
- **报修按钮**：仅离线设备（`status === 'OFFLINE'`）显示报修按钮
- **表单禁用 status**：新增/修改表单中 `delete this.form.status`，设备状态不由前端提交，完全由后端定时任务同步
- **搜索过滤**：状态下拉框支持按 ONLINE/OFFLINE 筛选

## 状态更新链路

设备状态由 **Prometheus SNMP 监控体系** 驱动，非前端轮询或 Java 定时任务：

```
SNMP Exporter (115.159.194.149:9116)
  └→ Prometheus (up==0 持续 2min → DeviceDown 告警)
      └→ AlertManager (ruoyi-webhook → 1.94.26.126:8090/device/alert/webhook)
          └→ AlertWebhookServiceImpl.handleAlert()
              └→ deviceService.updateDeviceStatus()
                  └→ DB iot_device.status 更新 + 状态日志 + SMS 通知
                      └→ 前端用户刷新列表 → GET /device/list → el-tag 渲染
```

> 端到端延迟约 3~4 分钟（SNMP 采集 60s + 告警持续 2min + AlertManager group_wait 10s + Webhook <1s）。用户手动刷新页面或切换分页时获取最新 `iot_device.status` 值。

## 组织架构树（TreePanel 侧边栏）

页面采用 `tree-sidebar-manage-wrap` 双栏布局（样式定义在 `ruoyi.scss`）：

```html
<div class="app-container tree-sidebar-manage-wrap">
  <tree-panel
    title="组织架构"
    :tree-data="deptOptions"
    search-placeholder="请输入部门名称"
    storage-key="device-dept-sidebar-width"
    :defaultExpandAll="true"
    @node-click="handleDeptNodeClick"
    @refresh="getDeptTree"
    ref="deptTreeRef"
  />
  <div class="tree-sidebar-content">
    <div class="content-inner">
      <!-- 搜索表单 + 统计卡片 + 工具栏 + 表格 + 分页 -->
    </div>
  </div>
</div>
```

### 数据流

```
getDeptTree() → deptTreeSelect() API (GET /device/deptTree)
  ├→ deptOptions → TreePanel 侧边栏渲染
  └→ enabledDeptOptions → filterDisabledDept() → 表单 Treeselect
       ↓
handleDeptNodeClick(data) → queryParams.deptId = data.id → handleQuery()
       ↓
listDevice({ deptId }) → MyBatis find_in_set(ancestors) 子部门过滤
       ↓
表格刷新 + 统计卡片联动
```

### 重置行为

- `resetQuery()` 清空 `queryParams.deptId` + 调用 `this.$refs.deptTreeRef.setCurrentKey(null)` 取消高亮
- 统计卡片点击"设备总数"直接触发 `resetQuery`（清空部门筛选）

## 部门选择器（Treeselect）

新增/编辑设备表单中使用 `@riophae/vue-treeselect` 组件选择归属部门：

```html
<el-form-item label="归属部门" prop="deptId">
  <treeselect v-model="form.deptId" :options="enabledDeptOptions"
    :show-count="true" placeholder="请选择归属部门" :disabled="isViewMode" />
</el-form-item>
```

- **选项来源**：`enabledDeptOptions` 由 `getDeptTree()` 从 `deptOptions` 深拷贝后经 `filterDisabledDept()` 过滤禁用部门
- **提交**：`form.deptId` 随新增/修改请求发送到后端，Mapper 写入 `iot_device.dept_id`
- **回显**：编辑设备时 `getDevice()` 返回 `deptId`，`this.form = response.data` 自动回填
- **表格展示**：`deptName` 列由后端 `LEFT JOIN sys_dept` 返回，无需前端额外处理
