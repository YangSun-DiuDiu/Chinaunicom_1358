## 公共查询片段 selectMeetingRoomVo

列表与详情复用的公共 SELECT，主表 `meeting_room` 用别名 `mr`，LEFT JOIN `sys_dept` 取部门名：

```sql
select mr.room_id, mr.room_name, mr.location, mr.capacity, mr.equipment,
       mr.status, mr.dept_id, sd.dept_name,
       mr.create_by, mr.create_time, mr.update_by,
       mr.update_time, mr.remark
from meeting_room mr
left join sys_dept sd on sd.dept_id = mr.dept_id
```

- 部门名 `dept_name` 仅查询关联，不落库（实体 `deptName` 非持久化字段）。
- **主表必须带别名 `mr`**：DeptScopeInterceptor 自动检测主表别名并追加 `mr.dept_id`，避免与 `sys_dept sd` 的 dept_id 歧义。

## 部门过滤条件

`selectMeetingRoomList` 增加 deptId 条件，实现**本部门 + 全部子部门**过滤（`find_in_set` 基于 `sys_dept.ancestors` 冗余字段）：

```xml
<if test="deptId != null and deptId != 0">
    AND (mr.dept_id = #{deptId} OR mr.dept_id IN (SELECT t.dept_id FROM sys_dept t WHERE find_in_set(#{deptId}, t.ancestors)))
</if>
```

## update 不含 dept_id（关键设计）

```xml
<update id="updateMeetingRoom" parameterType="MeetingRoom">
    update meeting_room
    <set>
        ... room_name / location / capacity / equipment / status / update_by / remark ...
        update_time = sysdate()
    </set>
    where room_id = #{roomId}
</update>
```

**为什么 update 不加 dept_id**：前端编辑表单不带 deptId，若 update SQL 含 dept_id，编辑时 `deptId=null` 会被 `DeptFillAspect` 误改为当前用户部门，导致会议室被"搬"走。设计决策：**归属仅在创建时决定**，编辑不可改。
