# 文档中心更新维护 Skill

## 概述

文档中心（http://192.168.1.60/doc）是一个**动态文档系统**，不是静态 Markdown 文件托管。核心机制：

```
源码目录 (ruoyi-system/src, ruoyi-ui/src/views, sql/)
    │
    └── DocServiceImpl 扫描引擎
            │  约定式映射：Controller → 后端/、Vue → 前端/、SQL → 数据库/
            │
            └── docs/ 目录（骨架 .md 文件）
                    │
                    └── DocController API (/doc/tree, /doc/content, ...)
                            │
                            └── DocTree + DocReader 前端双栏渲染
```

- **后端**：`DocServiceImpl.java`（扫描引擎，~600 行）
- **前端**：`ruoyi-ui/src/views/doc/index.vue`（双栏布局）+ `DocTree.vue` + `DocReader.vue`
- **API**：`DocController.java`（5 个接口，`/doc/*`，匿名可访问）
- **定时同步**：Quartz `docSyncJob`（每 60 秒），检测 commit 变化后自动触发扫描

## 文档目录结构

```
docs/
├── 01-设备管理/
│   ├── 后端/          ← Java Controller/Service/Mapper/Domain .md
│   ├── 前端/          ← Vue 页面 + JS API 文件
│   │   ├── list/
│   │   │   └── index.vue.md
│   │   ├── fault/
│   │   │   └── index.vue.md
│   │   └── ...
│   ├── 数据库/        ← SQL 文件 .md
│   └── README.md
├── 02-会议管理/
...
└── 13-.../
```

每个 `.md` 文件包含 YAML frontmatter：

```yaml
---
source: ruoyi-system/src/main/java/com/ruoyi/system/controller/DeviceController.java
type: Controller          # Entity | Service | Controller | Mapper | VuePage | JSAPI | DatabaseSQL
module: 设备管理
chapter: 后端
autoGenerated: false      # true=骨架(待填写), false=已人工编写
createdAt: Sun Aug 09 15:30:31 CST 2026
updatedAt: 2026-08-09
---
```

## 操作场景

### 场景 1：手动编写/更新单个文档

1. 找到对应的 `.md` 文件（根据目录结构或 `/doc/tree` API）
2. 编辑文件内容（写在 frontmatter 的 `---` 下方）
3. 将 `autoGenerated: true` 改为 `autoGenerated: false`（标记为已编写）
4. 更新 `updatedAt` 日期
5. 如需刷新到服务器：上传文件 + 无需重启后端（文件系统直读）

**手动编辑时前端标题规范**：

```markdown
# DeviceController — 设备管理接口

## 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | /device/list | 分页查询设备列表 |
```

### 场景 2：新增模块文档

如果系统新增了一个业务模块（例如"资产管理"），需要让它出现在文档中心：

1. 在 `docs/` 下建立对应目录（序号 + 模块名）：
   ```
   docs/14-资产管理/后端/
   docs/14-资产管理/前端/
   docs/14-资产管理/数据库/
   ```

2. **方式 A** — 调用后端同步 API 自动生成骨架：
   ```bash
   curl -X POST http://192.168.1.60:8080/doc/sync
   ```
   这会触发 `DocServiceImpl.syncAll()`，扫描所有源码目录并创建骨架 .md。

3. **方式 B** — 本地生成后上传：
   在本机启动后端 → 调用 `/doc/sync` → 生成的 docs/ 打包上传到服务器。

4. 骨架生成后，逐一编辑 .md 文件，将 `autoGenerated: true` 改为 `false`，填入实际内容。

### 场景 3：添加新的源码扫描规则

如果需要让扫描引擎识别新的源码目录或文件类型，修改 `DocServiceImpl.java` 中的映射逻辑：

| 方法 | 负责扫描 | 命名规则 |
|------|---------|---------|
| `scanJavaSources()` | Controller/Service/Mapper/Domain | 类名 → `类名.md` |
| `scanVueFiles()` | Vue 页面 + JS API 文件 | 文件名 → `文件名.md` |
| `scanSqlSources()` | SQL 文件 | 文件名去 `.sql` → `文件名.md` |

**⚠️ 修改扫描逻辑后的必要步骤**：
1. 编译 → 部署后端 JAR
2. 如果是已有文件命名规则变更，可能需要清理旧 .md 文件后重新同步

### 场景 4：刷新文档到服务器

**仅更新 docs/ 目录内容（不改代码）**，完整流程：打包 → 上传 → 解压 → 验证 → 清理。

```bash
# 1. 本地打包 docs/
tar -czf docs.tar.gz docs/

# 2. 通过 paramiko 上传并解压（遵循 CLAUDE.md 服务器连接规范）
python << 'PYEOF'
import paramiko
host, user, pwd = "192.168.1.60", "root", "Chinaunicom@1358"
c = paramiko.SSHClient()
c.set_missing_host_key_policy(paramiko.AutoAddPolicy())
c.connect(host, username=user, password=pwd, timeout=15)
sftp = c.open_sftp()
sftp.put("docs.tar.gz", "/home/zhihuiyuanqu20260907/docs.tar.gz")
sftp.close()
stdin, stdout, stderr = c.exec_command(
    "cd /home/zhihuiyuanqu20260907 && tar -xzf docs.tar.gz && rm docs.tar.gz && echo OK"
)
print(stdout.read().decode().strip())
err = stderr.read().decode().strip()
if err: print("STDERR:", err)
c.close()
PYEOF

# 3. 验证部署（以 AlertWebhookController.md 为例）
curl -s -w "\nHTTP:%{http_code}" \
  "http://192.168.1.60:8080/doc/content?path=docs/01-%E8%AE%BE%E5%A4%87%E7%AE%A1%E7%90%86/%E5%90%8E%E7%AB%AF/AlertWebhookController.md" \
  | tail -3

# 4. 清理本地临时文件
rm docs.tar.gz
```

**不需要重启后端** — `/doc/content` 接口直接读取文件系统。

**注意事项**：
- curl 验证时，路径中的中文字符需要 URL 编码（如 `设备管理` → `%E8%AE%BE%E5%A4%87%E7%AE%A1%E7%90%86`）
- 建议先 curl `/doc/tree` 确认模块出现在树形导航中，再检查具体文件 content
- Windows Git Bash 下 `sshpass`/`ssh` 命令行不可用，**必须用 paramiko**

**如果改了后端扫描代码**：按"仅后端"模式部署（编译 → scp JAR → kill → 重启）。

### 场景 5：强制触发服务器端同步

```bash
curl -X POST http://192.168.1.60:8080/doc/sync
```

或在管理后台 → 定时任务 → 手动执行 `docSyncJob`。

## Vue 页面文件命名规范

### 问题背景

所有 Vue 页面入口文件都叫 `index.vue`，自动生成的文档文件名全部是 `index.vue.md`，在目录树中无法区分。

### 解决方案

`DocServiceImpl.buildTreeNode()` 中已实现：当 `.md` 文件名为 `index.vue` 时，**树节点展示名自动加父目录前缀**。

| 实际文件路径 | 树节点展示名 |
|------------|------------|
| `前端/list/index.vue.md` | `list/index.vue` |
| `前端/fault/index.vue.md` | `fault/index.vue` |
| `前端/topology/index.vue.md` | `topology/index.vue` |
| `前端/repair/complete.vue.md` | `complete.vue`（非 index 不改名） |

### 骨架标题

新生成的骨架文件，`# ` 标题同样遵循此规则：
- `list/index.vue` → `# list/index.vue`
- `fault/index.vue` → `# fault/index.vue`

**手动编写时建议将标题改为中文**，例如：
```markdown
# 设备列表页 (list/index.vue)
```

## 重要注意事项

### 1. 骨架文件保护

- `autoGenerated: true` 的文件不会被**重新覆盖**（`scanVueFiles` / `scanJavaSources` 中 `Files.exists(md)` 检查）
- 一旦人工编辑并将 `autoGenerated` 改为 `false`，后续重新同步也不会覆盖
- **删除 .md 文件后**，下次同步会以新规则重新生成骨架

### 2. 孤本检测

`DocServiceImpl.markOrphanedFiles()` 会遍历 docs/ 目录，检查每个 .md 文件的 `source` 路径是否仍存在。如果源码文件已被删除/重命名，对应的 .md 会被标记 `orphaned: true`，前端展示为"孤本文档"。

### 3. 匿名访问白名单

文档中心无需登录即可访问，依赖以下配置：

| 配置位置 | 内容 |
|---------|------|
| `SecurityConfig.java` | `.requestMatchers("/doc/tree", "/doc/content", "/doc/status", "/doc/search").permitAll()` |
| `ruoyi-ui/src/router/index.js` | `/doc` 路由在 `constantRoutes` 中，`meta: { noAuth: true }` |
| `ruoyi-ui/src/permission.js` | `/doc` 在 `whiteList` 数组中 |

**⚠️ 新增接口后**：如果新接口也需要匿名访问，必须在 `SecurityConfig.java` 中添加 `permitAll()`。

### 4. 不重启即可生效的操作

| 操作 | 是否需要重启 |
|------|------------|
| 编辑 .md 文件内容 | ❌ 不需要 |
| 新增 .md 文件 | ❌ 不需要 |
| 上传 docs/ 目录（tar + paramiko） | ❌ 不需要 |
| 调用 /doc/sync | ❌ 不需要 |
| 修改扫描逻辑（DocServiceImpl） | ✅ 需要重启后端 |
| 修改前端 DocTree/DocReader 组件 | ✅ 需要重新构建前端 |
| 修改 SecurityConfig 白名单 | ✅ 需要重启后端 |

- **所有服务器上传统一使用 paramiko**（遵循 CLAUDE.md 服务器连接规范），禁止 `ssh`/`scp` 命令行
- curl 验证部署时，路径中的中文字符需 URL 编码（如 `设备管理` → `%E8%AE%BE%E5%A4%87%E7%AE%A1%E7%90%86`），建议先 `/doc/tree` 获取精确 path 再拼 content 请求

### 7. 批量编写文档最佳实践

当需要一次性更新同一模块的多个文档（如 README + 若干后端/前端子文档）时：

1. **先读源码** — 读取涉及的所有 Java/Vue 源文件，确保文档准确
2. **README 先行** — 先写模块 README（架构全景图），再补充子文档（单文件详解）
3. **README 引用子文档** — README 中用相对链接引用子文档，如 `[AlertWebhookController](后端/AlertWebhookController.md)`
4. **统一更新 frontmatter** — 所有编辑过的文件 `autoGenerated` 改为 `false`，`updatedAt` 改为当天日期
5. **一次性部署验证** — 所有文件写完后一次 tar + paramiko 上传，然后用 curl 验证 2~3 个关键文件
6. **检查填充率** — 部署后 `curl /doc/tree` 查看模块 `totalFiles` vs `filledFiles`，确认编写比例
